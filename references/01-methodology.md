## 1. 产品经理类型与岗位定位

AI 产品经理分三层，投递前须明确岗位属于哪层，因为能力要求不同：

- **应用层（多数投递岗位）**：重点考察需求认知与评估（需求收集、客户管理、
  预期管理、项目推进），以及对 AI 的理解。**本 skill 默认按应用层组织。**
- **模型层**：需要一定算法能力与技术理解能力；同样考察客户/预期管理与项目推进。
  若用户投模型层，自我介绍与项目介绍中应额外突出算法理解、技术选型的深度。
- **基础设施层**：偏底层，简历需突出工程与平台能力（本方法论较少覆盖）。

## 2. 能力模型（简历要突出的核心）

从 AI 产品完整工作流程反推每个节点对应的能力，简历里的每句话都应对应其中之一：

| 工作节点 | 对应能力 |
|---|---|
| 需求挖掘 | 客户沟通与需求预期管理、对问题的深度思考 |
| 需求评估 | 需求抽象、优先级判断、价值评估 |
| 技术调研 | 对 AI 核心技术的了解（Prompt、技术边界、常见方案） |
| 项目推进 | 项目把控、风险把控、跨部门协同、向上汇报 |
| bad case 优化 | 熟悉一系列 AI 技术的常用解决方案 |
| 产品规划 | 产品能力、迭代规划 |
| （贯穿） | 持续学习能力——AI 技术持续演进，须体现持续获取动态的习惯 |

## 3. 简历撰写总原则

- **目标读者是面试官**：让面试官判断你符合岗位人物画像。每句话服务于突出某项能力。
- **拒绝通用化表述**：能套用到任何项目的句子等于没写。必须具体到"谁的什么痛点、
  用什么手段验证并解决"。
- **量化结果**：收益/指标尽量用数字。无真实数据时写定性结果或标 `[待补数据]`，**禁止编造或「合理估算」百分比**。
- **格式**：用超级简历等工具制作，导出 PDF；经历多控制 1~2 页，经历少压到 1 页。
- **文件名**：投递后面试官先看到文件名，应含姓名 + 工作年限 + 应聘岗位。

### 项目整理（撰写前的准备）
写简历前先把过往经历梳理进一个文档，含：项目名称、需求背景、持续时间、目标与要
解决的问题、衡量指标、项目过程、你做了什么、收益、收获、做得不好的点及改进措施
（改进措施可采用逐级反馈流程：周会 → 周报 → 向上反馈）。梳理清楚才知道项目解决了
什么、持续多久、收益如何。

## 4. 五大板块撰写规则

### ① 基本信息
简洁：姓名、手机号、邮箱即可，突出关键信息。年龄、政治面貌等一般无需（除少数政府
背景单位）。照片：形象是加分项可贴，否则不贴也无妨，对 AI 产品经理岗无实质影响。
专业技能不要罗列过多。

### ② 自我介绍（自我评价 / 核心优势）
作用：开篇传达"我是这样一个人"，是**引子**，提前埋伏笔，随后由项目介绍来论证。
**切忌过长**（会消耗版面），围绕产品经理能力要求写 3~4 条。三大方面：

1. **优势**：行业优势或经验优势（此前所在行业、时长、内容），可一句话概括，
   如"三年 AI 产品经验"。
2. **核心技能**：从产品经理工作流程中提炼可作为核心技能的项；技术出身是加分项
   （既有产品思维又有技术思维，凸显业务理解），可总结为"丰富的客户对接与项目
   管理经验，擅长需求评估、需求抽象与项目逻辑表达"。
3. **过往产品经验**：如"拥有多个 0 到 1 的 AI 产品经验"——信息量大，暗示熟悉完整
   产品流程、了解风险把控/项目管理/向上汇报。

自我介绍还应体现 **AIGC 认知**：
- 大模型认知：了解底层技术原理与整体架构；了解当前市场、融资、发展趋势
  （可借助《四十二章经》等播客搭建认知框架）。
- Agent 认知：实际用过 Coze / 文生图 / 文心一言等平台解决真实痛点，并借此打磨
  Prompt 构建能力。
- AI 项目落地：拥有智能客服 / 企业知识库 / 合同审查等领域的落地经验。
- 持续学习：说明以何种方式（每日/每周）持续获取 AI 最新动态。

**示例**："拥有三年互联网产品经验，熟悉完整产品流程，具备跨部门协同经验，主导过
5 个项目的产品迭代建设。技术侧对前后端技术栈有一定认知，能有效沟通、驱动跨部门
协作，保证项目正常推进。"

### ③ 教育经历
若非 985/211 等重点院校，此板块优先级后置（放靠后，避免面试官第一眼聚焦）。
只需：学校、专业、学历、在校时间。社招同学 GPA / 证书通常无需写。可加"985 / 211"
标识（部分面试官对院校层次无明确概念，标识利于形成初步印象）。

### ④ 工作经历
从公司视角出发，**按时间倒序**（由近到远）。近两三年经历尽量多用 AI 相关词汇
（利于 Boss 直聘等平台关键词抓取）。每段写公司基本信息 + 岗位，并用一段内容概括
当时负责的工作。

**描写框架**：
1. 第一句：快速概括你负责什么、为什么由你负责。
2. 随后：为此做了哪些事、创造了什么价值、取得了什么结果。
> 思路：一句话高度概括 → 分步阐述 → 用结果收尾。

**示例**："在此期间主导了某系统的搭建及商业化。整体主要负责 AI 产品的能力建设与
商业化，通过完成某项目、某项目的构建，实现 AI 主中台能力建设与整体商业化，推动
跨部门协同，客户咨询率下降 XX%。"

### ⑤ 项目介绍
运用 **STAR 法则**：
- **背景 Situation**：做这件事的整体背景。
- **目标 Task**：要达成什么目标。
- **行动 Action**：采取了哪些行动、满足了用户什么诉求。
- **结果 Result**：取得了什么结果 + 后续优化方向。

应体现 AI 产品经理必经流程：方案调研与评估、需求分析与产品规划、bad case 反馈；
建议列出**技术选型**。

撰写要点：
1. 项目名称不要堆叠两个名称。
2. 名称**通俗易懂**（面试官不了解你司业务），主标题后可加**副标题标技术栈**，
   如 "LLM + RAG"。
3. 重点是项目背景、工作内容、成果的阐述。

**呈现框架**：项目简介 → 时间 → 为什么做（背景）→ 做了哪些事 → 最终成果。

## 5. 案例分析要点（正反例）

- **好版面**：简约大方、无多余修饰。
- **反例一——解决方案太空**：如"新增商品及订单对外接口"看不出做了什么、是否本人
  主导、体现什么能力，属"为写而写"。"搭建开放平台"未说明是否完成、如何搭建、
  用什么体系、为什么搭建、用什么指标证明有效。→ 必须补足"怎么做 + 为什么 + 指标"。
- **反例二——排版花哨**：低质模板、大量空白、无关信息（年龄/政治面貌）、专业技能
  堆砌。→ 删冗余，突出能力。
- **反例三——缺小标题、只有背景没有动作**：项目经历一大段无小标题，读者抓不住重点；
  只交代背景与成果、不写具体做了什么。→ 加小标题，补"做了哪些事"。

## 6. 电话面试项目介绍话术

面试官关注三点：**用户价值、结果、手段**。

- **第一句**：项目面向谁 + 他们的痛点 + 你的解决方案。
  例："该项目面向电商平台的商家群体，我提供了一套咨询服务。"
- **第二句**：用户具体痛点（咨询量大、流程不完善、满意度不高）+ 解决方案
  （如基于 RAG 框架的大模型产品）+ 价值目标（减轻客服压力、提升体验）+ 成果
  （客户咨询率等指标）。
- **第三，工作内容**：方案调研与评估、需求分析、产品设计、bad case 优化。撰写时
  始终自问"这句话想传达什么能力"，按能力分类概述（如"用户调研与需求评估"对应
  客户管理、需求深度评估、问题思考逻辑）。**不要所有简历套同一视角，业务背景不同。**
- **最后，产品结果**：用数据体现（多少用户在用、绩效提升多少、成本/资源节约多少），
  分点概述。
