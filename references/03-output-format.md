# 输出格式：Markdown 简历模板

> Mode A 生成与 Mode B / Full Pipeline **终稿**均必读。
> 项目介绍**一律使用 STAR**（背景 / 目标 / 主要工作 / 成果）。
> Mode B 只升级措辞与机制密度，**不改变 STAR 版式**。

## 文件名建议
`姓名_工作年限_应聘岗位.pdf`，例：`孟星_4年_AI产品经理.pdf`

## Markdown 结构

```markdown
# {姓名}
{应聘岗位} · {工作年限}经验 · {城市（若填）}
{手机号} | {邮箱}

## 自我介绍
- {优势条：改写为具体能力，非套话}
- {核心技能条}
- {AI/大模型认知条}
- {AI 项目经验条}
- {持续学习条（若填）}

## 工作经历
### {公司} · {岗位}｜{起止时间}
{职责概括一句话}。{分步阐述做了哪些事，近两三年多用 AI 相关词汇}。{量化结果}。
<!-- 多段按时间倒序重复 -->

## 项目介绍
### {通俗项目名}（{技术栈副标题}）｜{项目时间}
- **背景**：{S}
- **目标**：{T}
- **主要工作**：{A，分点}
- **成果**：{R；仅真实数据，无数据则定性或 `[待补数据]`}
<!-- 多个项目重复 -->
```

### Mode A 骨架 vs Mode B 冲刺（同一 STAR 壳）

| STAR 字段 | Mode A（骨架） | Mode B 升级后（冲刺，仍用 STAR） |
|---|---|---|
| **背景** | 业务场景与原始问题，事实完整即可 | 写入已确认的核心矛盾 + 痛点词（原因（结果词）），体现复杂场景 |
| **目标** | 要达成什么 | 写入架构/能力升级方向与价值组合（来自总述，不含具体数字） |
| **主要工作** | 方案调研/需求/设计/bad case 等分点 | 写入已确认的机制 Bullet（可保留能力模块名作小标题或句首），强调状态升级 |
| **成果** | 真实结果或 `[待补数据]` | 写入成果段：效果提升 + 能力沉淀 + 后续扩展；**量化数据集中在此** |

Mode B 过程中的「总述双版本 / 逐条 Bullet」是**中间打磨**，确认后必须折叠进上表四栏。  
终稿**禁止**使用「项目总述段落 + 能力模块 Bullet 列表」替代 STAR。

## 若填了 JD：附岗位匹配说明
在简历正文之后另起一段"岗位匹配说明"（格式见 `04-jd-tailoring.md` 第五节），
列出岗位类型判定、已匹配项、建议补强项。此段是给用户的辅助信息，投递前可删。

## 改写要点（不要原样拼接用户输入）
- 自我介绍每条都要能对应一项能力；删掉可套用到任何人的空话。
- 工作经历遵循"一句话概括 → 分步 → 结果"，动词开头，突出主导性。
- 项目「主要工作」分点写；Mode B 后每点尽量带机制与状态升级，并对应一项 PM 能力。
- 所有收益尽量量化；无真实数据不编造，标 `[待补数据]`。
- Full Pipeline / Mode B 终稿项目段：**STAR 版式 + Mode B 级内容**。

## 生成后
逐板块用一两句说明"这里为什么这么写、体现了什么能力"，再问用户是否要转 Word / PDF。
