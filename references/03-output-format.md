# 输出格式：Markdown 简历模板

> 第 2 步必读。把用户输入**改写**成符合方法论的简历语言后，按下面结构组织。
> 顺序可依方法论调整（如非重点院校则教育经历后置）。

## 文件名建议
`姓名_工作年限_应聘岗位.pdf`，例：`孟星_4年_AI产品经理.pdf`

## Markdown 结构

```markdown
# {姓名}
{应聘岗位} · {工作年限}经验 · {城市（若填）}
{手机号} | {邮箱}

## 自我介绍
- {优势条：改写为具体能力，非套话}
- {核心技能条}
- {AI/大模型认知条}
- {AI 项目经验条}
- {持续学习条（若填）}

## 工作经历
### {公司} · {岗位}｜{起止时间}
{职责概括一句话}。{分步阐述做了哪些事，近两三年多用 AI 相关词汇}。{量化结果}。
<!-- 多段按时间倒序重复 -->

## 项目介绍

### Mode A / 骨架版（STAR）
### {通俗项目名}（{技术栈副标题}）｜{项目时间}
- **背景**：{S}
- **目标**：{T}
- **主要工作**：{A，按方案调研/需求分析/产品设计/bad case 分点}
- **成果**：{R；仅真实数据，无数据则定性或 `[待补数据]`}

### Mode B / 冲刺版（升级后替换上方 STAR）
### {通俗项目名}（{技术栈副标题}）｜{项目时间}
{项目总述：矛盾 + 架构升级 + 价值组合，不含具体数字}

- **{能力模块名}**：{痛点→机制→状态升级→价值；不含量化数据}
- **{能力模块名}**：{…}
- **成果**：{效果提升 + 能力沉淀 + 后续扩展；量化数据集中在此}
<!-- 多个项目重复；总述句式须差异化 -->

## 教育经历
### {学校}{（985/211 标识，若有）} · {专业} · {学历}｜{在校时间}
<!-- 非重点院校时，本板块置于项目介绍之后、靠简历末尾 -->
```

## 若填了 JD：附岗位匹配说明
在简历正文之后另起一段"岗位匹配说明"（格式见 `04-jd-tailoring.md` 第五节），
列出岗位类型判定、已匹配项、建议补强项。此段是给用户的辅助信息，投递前可删。

## 改写要点（不要原样拼接用户输入）
- 自我介绍每条都要能对应一项能力；删掉可套用到任何人的空话。
- 工作经历遵循"一句话概括 → 分步 → 结果"，动词开头，突出主导性。
- 项目"主要工作"分点写，每点尽量点明体现了哪项能力（客户管理 / 需求评估 /
  技术理解 / 项目推进 / bad case 优化）。
- 所有收益尽量量化；无真实数据不编造，标 `[待补数据]`。
- Full Pipeline 终稿的项目段应使用 Mode B 冲刺版结构，不再保留 STAR 骨架（除非用户要求保留对照）。

## 生成后
逐板块用一两句说明"这里为什么这么写、体现了什么能力"，再问用户是否要转 Word / PDF。
